# 传送带动态抓取 Spec

**Date**: 2026-08-22
**Status**: Draft（待用户审阅）
**Scope**: 在传送带持续运行（匀速）时对移动物体进行动态抓取。新增传送带方向标定、速度预测模块、斜线随动下降抓取序列、动态抓取 GUI 模式、红外漏抓兜底
**Depends on**: 现有静态分拣流水线（auto_sorting_action.py / sorting_gui_client.py / realsense_yolo_node.py / stm32_conveyor.py）、/detection_info 协议、IK/笛卡尔运动控制、碰撞检测机制

---

## Why

当前系统实现的是"传送带停止 → 静态抓取"模式：物体跨越分界线后传送带停止，等待物体静止再抓取。该模式单位时间吞吐量受限于传送带启停与物体稳定时间。

目标：开发**动态抓取**——物体在匀速传送带上持续移动，机械臂直接截住移动中的物体进行抓取，无需停带。关键难点：

1. 基坐标系下物体速度向量怎么来（STM32 速度 + 传送带方向标定，还是视觉帧间位移）
2. 视觉/动作延迟补偿（检测管线延迟 + 下降耗时内的位移）
3. 抓取时夹爪与物体的水平速度匹配（斜线随动下降解决）

## 已确认约束（与用户讨论结论）

- 传送带线速度 **0.02–0.15 m/s 范围内可调**（STM32 上报，已实测为真实值，无需二次校正）
- 抓取区为**固定抓取区**：机械臂在传送带上一个固定区域（工作空间内）拦截物体
- 机械臂下降/抓取时会**遮挡俯视相机视野**；抓取瞬间不能依赖视觉闭环，需靠预判 + 前馈
- **漏抓兜底（主用视觉分界线）**：在画面右侧（传送带下游）设定一条可细调的分界线，若分界线右侧有物体则立刻停带 → 静态抓取 → 重启带
- **红外传感器**（STM32 `O` 字段，已反转：True=有物体）位于下游出口侧，**实测不灵敏，降级为辅助信号**（不作为漏抓判定主依据）
- 物体**连续送入、间距不定**；漏抓时停带 → 静态抓取 → 重启带
- 眼在手相机为机械臂厂家随附（非 D455、近距离深度可靠，但**仅支持 ROS1**）——第一版**不启用**，作为二期备选（见"眼在手相机决策"）

## 技术设计

### 一、传送带方向标定（一次性）

相机画面横轴与传送带不平行（有夹角），必须先确定**传送带方向在基坐标系下的单位向量 `d̂_base`**。

#### 标定方法
- 放置特征物体在传送带上，以固定速度运行 2–3 秒
- 俯视相机持续记录 `base_position_m` 轨迹（若干采样点）
- 对轨迹做 PCA / 最小二乘直线拟合 → `d̂_base = (dx, dy)`（z 分量≈0）
- **同时校验 STM32 速度**：视觉位移 ÷ 时间 与 STM32 上报 v 对比；一致则信任 STM32，偏差则记录比例系数用于校正
- 结果保存 `conveyor_calib.json`，动态模式启动时加载

### 二、速度数据通路与预测模块（视觉融合）

#### 速度数据通路
- 串口 `exclusive=True`：同一时刻仅一个进程能打开串口。现传送带 worker 进程在 GUI 侧读串口
- 新增 `/conveyor_status` 话题（JSON：speed、object_detected、motor_running、motor_direction，10Hz），由传送带 worker 进程发布
- `auto_sorting_action.py` 订阅该话题，维护最新线速度 `v_stm32`（保留滑动窗口滤波）

#### VelocityPredictor
- **前馈**：`v_base = v_stm32 × d̂_base`
- **视觉融合**：物体可见时，用 `base_position_m` + `header_stamp`（检测时刻）做窗口线性拟合估计 `v_vis`，与 v_stm32 交叉验证；偏差大时校正 d̂ 漂移或速度波动
- **延迟补偿**：检测位置对应 `header_stamp` 时刻而非接收时刻，预测用 `p(t) = p_meas + v_base × (t − t_meas)` 显式补偿视觉管线延迟（YOLO+深度+EMA+变换约 100–300ms；0.15 m/s 时 200ms≈3cm，必须补偿）

### 三、抓取执行序列（斜线随动下降）

#### 新增位姿
- `P_HOVER`：抓取区中心上方悬停位（基坐标系，夹爪张开，安全高度）
- `P_SHADOW`：物体当前预测位置正上方的影子点（动态计算）

#### 序列
1. **横向对齐（TRACKING）**：物体进入上游触发区 → 机械臂移动到 P_SHADOW（物体可见，视觉引导对齐正上方）
2. **随动下降（DESCENDING）**：物体预测进入抓取区 → 执行**斜线笛卡尔路径**：水平方向 = 传送带方向、水平速度 ≈ v、垂直降到抓取高度。臂与物体同步以 v 移动，全程保持正上方，对下降耗时不确定性不敏感
3. **夹取（GRASPED）**：到底夹爪闭合
4. **带前向分量抬起（PLACING）**：脱离传送带 → 放料框 → 回 P_HOVER

#### 姿态与碰撞
- 抓取姿态用最后一次可见检测的 PCA 短轴朝向（物体在带上不旋转）
- 碰撞策略沿用现有：下降时禁用传送带碰撞体，回 P_HOVER 后恢复

### 四、状态机 / GUI 集成

- 新增 GUI 模式按钮"**动态抓取**"（区别于现有自动分拣）
- 状态机：`IDLE → TRACKING → DESCENDING → GRASPED → PLACING → IDLE`，循环拦截
- 传送带持续运行，速度实时显示（四位小数）
- 动态模式中禁用手动按钮、屏蔽弹窗（沿用现有约定）
- 停止按钮：完成当前任务 → 停带 → 回待机位

### 五、漏抓兜底（视觉分界线 + 红外辅助）

- **主用视觉分界线**：在画面右侧（传送带下游）设定一条可细调的分界线（复用现有 `_pick_object_right_of_line()` 模式），其位置由用户实测细调
- 动态模式中持续检测：若**分界线右侧存在物体**且机械臂空闲/未在拦截它 → **停带 → 静态抓取（复用现有 sort 序列）→ 重启带**
- **红外传感器作辅助**：STM32 `O` 字段（已反转）实测不灵敏，不作为漏抓判定主依据，仅作参考/告警
- 防止漏抓物体被带出工作范围丢失

### 六、错误处理与测试

- 预测失败 / IK 失败 / 拦截未中 → 回退"停带静态抓取"或跳过（沿用现有重试机制）
- 急停、碰撞检测策略复用现有逻辑
- 测试递进：
  1. 空跑验证：只预测+跟踪+下降不夹取，打点对比预测与实际到达位置/时刻
  2. 低速 0.02 m/s → 中速 0.08 → 高速 0.15 m/s

## 眼在手相机决策

**第一版不启用**眼在手相机。理由：
1. 其为机械臂厂家随附相机，**仅支持 ROS1**，当前整栈为 ROS2 Humble，接入需 ros1_bridge 桥接 + 眼在手手眼标定 + TF + 新检测节点，复杂度陡增
2. 红外传感器 + 停带兜底方案已优雅解决"漏抓"，不需要眼在手做最后精修
3. 核心动态抓取路径（速度前馈 + 预判拦截/斜线随动下降）不依赖眼在手
4. 若实测残余误差超出夹爪容差，二期再评估经 ros1_bridge 接入眼在手做最后对准精修

## ADDED Requirements

### Requirement: 传送带方向标定工具
系统 SHALL 提供一次性标定工具，确定传送带方向在基坐标系下的单位向量 `d̂_base` 并保存到 `conveyor_calib.json`。

#### Scenario: 采集物体轨迹并拟合方向
- **WHEN** 用户将特征物体放置在运行的传送带上，标定工具采集 2–3 秒 `base_position_m` 轨迹
- **THEN** 对轨迹做 PCA / 最小二乘直线拟合得到 `d̂_base = (dx, dy)`（z 分量≈0）
- **AND** 将结果写入 `conveyor_calib.json`（含 dx、dy、采集时间、速度校验信息）

#### Scenario: STM32 速度幅值校验
- **WHEN** 标定工具同时获得视觉帧间位移与 STM32 上报速度
- **THEN** 计算视觉位移/时间与 v_stm32 的比例关系
- **AND** 比例在容差内（如 ±5%）则记录"无需校正"，超出则记录比例系数供预测模块使用

### Requirement: 传送带状态话题
系统 SHALL 提供 `/conveyor_status` 话题（String JSON），由传送带 worker 进程以 10Hz 发布实时状态，供 action 节点订阅。

#### Scenario: 速度实时发布
- **WHEN** 传送带 worker 进程持续读取 STM32 串口
- **THEN** 每 100ms 解析状态帧（V/O/M1/M2），滑动窗口滤波后以 JSON 发布到 `/conveyor_status`
- **AND** JSON 包含字段：`speed`（m/s，滤波后）、`object_detected`（已反转）、`motor_running`、`motor_direction`、`connected`

### Requirement: 速度预测模块
系统 SHALL 提供 `VelocityPredictor`，融合 STM32 速度前馈与视觉观测，实现延迟补偿的常速度位置预测。

#### Scenario: 前馈速度计算
- **WHEN** 动态抓取运行且 `conveyor_calib.json` 已加载
- **THEN** `v_base = v_stm32 × d̂_base`
- **AND** 速度随 v_stm32 更新（保留滑动窗口滤波）

#### Scenario: 视觉融合校验
- **WHEN** 物体在俯视相机视野内
- **THEN** 用 `base_position_m` + `header_stamp` 做窗口线性拟合估计 `v_vis`
- **AND** v_vis 与 v_stm32 交叉验证；持续偏差超阈值时校正方向/速度

#### Scenario: 延迟补偿预测
- **WHEN** 需要预测物体未来位置
- **THEN** `p(t) = p_meas + v_base × (t − t_meas)`，其中 `t_meas` 为 `header_stamp`（检测时刻）而非接收时刻
- **AND** 显式补偿视觉管线延迟，保证 0.15 m/s 时预测误差在夹爪容差内

### Requirement: 动态抓取命令与执行序列
系统 SHALL 在 `auto_sorting_action.py` 新增动态抓取命令，执行斜线随动下降序列。

#### Scenario: 横向对齐
- **WHEN** 俯视相机检测到物体进入上游触发区
- **THEN** 机械臂移动到 P_SHADOW（物体当前预测位置正上方），保持视觉引导对齐

#### Scenario: 斜线随动下降
- **WHEN** 物体预测进入抓取区
- **THEN** 执行斜线笛卡尔路径：水平方向 = 传送带方向、水平速度 ≈ v、垂直降到抓取高度
- **AND** 全程保持物体正上方，对下降耗时不确定性不敏感
- **AND** 下降期间禁用传送带碰撞体

#### Scenario: 夹取与放置
- **WHEN** 夹爪到达抓取高度
- **THEN** 闭合夹爪 → 带前向分量抬起脱离传送带 → 放料框 → 回 P_HOVER
- **AND** 回 P_HOVER 后恢复传送带碰撞检测

### Requirement: 动态抓取 GUI 模式
系统 SHALL 在 GUI 新增"动态抓取"模式，独立于现有自动分拣。

#### Scenario: 模式启动与运行
- **WHEN** 用户点击"动态抓取"按钮
- **THEN** 传送带持续运行（不因抓取而停止），状态机进入 `IDLE → TRACKING → DESCENDING → GRASPED → PLACING` 循环
- **AND** 禁用手动按钮、屏蔽弹窗，实时显示传送带速度（四位小数）

#### Scenario: 停止动态抓取
- **WHEN** 用户点击停止按钮
- **THEN** 完成当前任务后停止传送带、回待机位、恢复手动按钮

### Requirement: 视觉分界线漏抓兜底
系统 SHALL 在动态模式中通过画面右侧（下游）可细调分界线检测漏抓，停带后静态抓取。

#### Scenario: 漏抓触发（视觉分界线）
- **WHEN** 画面右侧（下游）分界线右侧存在物体，且机械臂空闲/未在拦截该物体
- **THEN** 停止传送带 → 复用现有静态 sort 序列抓取该物体 → 重启传送带
- **AND** 分界线位置可调（GUI 参数，用户实测细调），复用现有 `_pick_object_right_of_line()` 选择逻辑

#### Scenario: 红外传感器辅助
- **WHEN** STM32 `O` 字段（已反转）指示出口有物体
- **THEN** 仅作参考/告警显示，不作为漏抓判定主依据（实测不灵敏）

### Requirement: 错误处理与递进测试
系统 SHALL 提供错误回退与递进测试路径。

#### Scenario: 预测/IK 失败回退
- **WHEN** 动态拦截预测失败、IK 失败或拦截未中
- **THEN** 回退"停带静态抓取"或跳过该物体（沿用现有重试机制）
- **AND** 急停、碰撞检测策略复用现有逻辑

#### Scenario: 递进测试
- **WHEN** 验证动态抓取
- **THEN** 先空跑验证（预测+跟踪+下降不夹取，打点对比预测与实际到达位置/时刻）
- **AND** 依次以 0.02 / 0.08 / 0.15 m/s 递进实测抓取
