日期：2026-10-19（Asia/Shanghai）
状态：功能与主页视觉方向已由用户确认；其余页面预览交付供审阅，尚未开发软件。

执行入口：[详细实施计划与原始问答](../plans/2026-10-19-piper-workbench-plan.md)。

## 1. 目标与优先级

把现有 Piper 抓取系统整合成可从 Ubuntu 桌面打开的独立上位机软件。关闭 Codex 不影响软件完整性、后台程序和已保存数据。面向用户日常实验开发，优先复用已跑通的程序，降低启动、调参、标定、采图和排错的操作成本。

优先级由高到低：

1. 现有抓取行为与标定方式得到正确复用，尤其保留动态抓取性能。
2. 已确认的操作可在工作台完成，组件可单独启动，状态真实可见。
3. 前端遵循预览布局与本规格中的交互、中文文案和状态说明。
4. 文件、日志、标定来源可追溯，软件运行独立于 Codex。

此次交付包含计划、需求原文、问答、六页预览；实现交给另一个 agent。不要把设计效果图或离线界面当作实机验收。

## 2. 已确认的产品决策

| 项目 | 必须实现的行为 |
|---|---|
| 抓取模式 | D455 动态抓取、D455 静态抓取、Dabai 静态抓取，主页仅这三类抓取入口 |
| 双相机 | 同时采集、同时 YOLO 检测、同时显示画面；选模式只改变抓取数据源 |
| D455 静态 | 单次抓取和连续自动分拣均保留，复用现有停带抓取流程 |
| Dabai 静态 | 选择目标后单次抓取 |
| 动态抓取 | 复用现有持续供带、预测和拦截流程 |
| 正常释放后返回 | D455 静态回待机位；Dabai 回观察位；动态回现有动态准备位 |
| 放置方式 | 手动统一放置、按识别类别分配两种方式 |
| 放置方案 | 名称、0～5 个去程途经点、一个最终释放点 |
| 示教 | 用户通过机械臂实体按钮进入示教，工作台读取实际关节角并保存 |
| 参考位置 | 待机位、Dabai 观察位均可示教重新保存；动态准备位由原流程产生 |
| 启动 | 独立组件按钮＋一键启动全部，只启动缺少部分，已运行部分复用 |
| 碰撞后恢复 | 手动一键重做 CAN 激活、机械臂激活、T1 重启；不因 CAN/T1 表面在线跳过 |
| 连接异常识别 | 当前 T1 的 Agx_arm is not connected, cannot control 警告触发恢复提示，不能单独认定碰撞 |
| 关闭窗口 | 完成当前这个物体的抓放后暂停，保留后台节点 |
| 标定基线 | 以主目录这两天现场正在使用的程序、操作方式和实际文件格式为准 |
| 标定应用 | 按钮主动选用、展示原始误差与生效状态，不新增审批流程 |
| 语言 | 尽量中文；专业标识、原始日志和路径保留原文 |
| 风格 | 浅色，白/黑/蓝为主，精致动效，六页左侧导航 |
| 主页布局 | 左侧上下双画面、中间较大三维视图、右侧操作；分栏可调宽 |
| 移除入口 | 新工作台不包含 GraspNet 和蓝方块功能，不启动对应服务 |

### 2.1 实现默认值

下列是用户接受整体方向后采用的具体实现默认值，不冒充逐条原话：

- 六个导航入口：抓取、调试、连接、标定、图片采集、日志。
- 旧手动坐标与任务队列保留在“调试 → 高级”，不占主页。
- 按类别分配有一个默认放置方案，未匹配类别使用默认方案。
- 图片采集支持单张和定时采集，可选一台或两台；仅保存原始彩色图，不做训练、标注。
- 参数更新按帧或抓取周期边界应用，当前动作不被中途改写。
- 旧 GUI 保留为回退入口，新桌面快捷方式指向工作台；两者不同时争用串口和任务调度。
- 不新增账号、云服务、数据库、遥测上传、插件系统或通用工作流引擎。

### 2.2 状态与操作

健康状态用于观察和排错，各功能不依赖全系统“全绿”。相机没启动时可以编辑方案、看历史日志、管理标定和启动其他组件；YOLO 没运行时可以采原始图、手动规划机械臂。某次操作依赖的数据或服务缺失，返回该操作的实际错误。

继续使用现有底层运动限制、急停、数值和坐标语义检查。不要新增“所有组件就绪”“必须完成校准审批”“只要 T5/T6 存在就禁止调试”的界面拦截。特别适配 TCP 验证中的旧节点存在性限制。

## 3. 运行与架构

### 3.1 固定技术方向

- 前端：Qt 5 Widgets / C++，浅色样式和 QPropertyAnimation；直接链接 RViz 原生库。
- 三维：复用 rviz_common 和 moveit_rviz_plugin/MotionPlanning，使用项目真实 URDF/SRDF、规划场景与 TF。
- 手动规划：MoveIt 原生目标状态与规划/执行接口。末端交互标记、J1～J6 输入共用同一目标状态。
- 启动使用 ROS launch 传入现有建模逻辑产生的 robot_description/semantic/运动学和 TCP，规划组 arm、末端 tcp_link、固定坐标 base_link；新节点不自动继承远程参数。
- 后端：系统 Python 3 的常驻工作台服务，复用 rclpy、运行启动器、现有抓取与标定程序。
- 本地控制通信：项目内 Unix 域套接字，逐行 JSON；不开放网络端口。
- 相机画面与三维反馈：前端直接订阅 ROS，图像不经 JSON/base64 转发。
- YOLO：一份模型处理两台相机，复用现有视觉节点的双路代码。

本机已只读确认 Qt5Widgets 5.15.3、X11，以及 RViz/MoveIt 的相关头文件。尚未编译或验证工作台内嵌三维视图。执行时先完成最小嵌入验证，再铺页面；不得以静态机械臂图片替代真实三维功能。

如果实际嵌入暴露架构问题，先提交编译/运行证据和问题说明，由主执行 agent 重新决策；不擅自改成整套网页三维重写。

### 3.2 进程职责

| 进程 | 职责与生命周期 |
|---|---|
| Qt 工作台 | 页面、交互、图像显示、RViz、手动目标/规划控制；关窗不杀 T1/T5 |
| 工作台后台服务 | 组件编排、任务派发、传送带唯一串口连接、标定会话、采图、日志汇集；UI 断开后仍能完成收尾 |
| 现有 T1 / MoveIt | 机械臂驱动、关节反馈、模型、控制器、规划器 |
| 两个相机驱动与 TF | 各自独立启动、显示和诊断 |
| 双路 YOLO | 单模型、两路输入、各自结果话题；缺一路数据不拖垮另一路 |
| T5 抓取动作 | 原抓取算法，增加放置方案、按模式返回、周期结束暂停接口 |
| 标定工具 | 原算法和文件格式，伪终端连接现有交互，按钮负责发采样/求解命令 |

伪终端（pty）让程序像在普通终端中一样接收 Enter/d/q/c，避免重写采集算法。PTY 输出保留完整日志；采样数量和结果从会话文件读取，不只靠匹配终端文字。

后台服务使用独立进程组和现有 ProcessManager 登记；不要把它变成 UI 的 daemon 子进程，也不要沿用“父窗口消失就清理全部 session 组件”的旧行为。T1/T5 保持原进程，打开窗口不自动激活或移动机械臂。

### 3.3 窗口关闭和暂停

- 正常关闭：请求 pause_after_cycle，UI 可以关闭；服务负责等待当前物体完成、停止派发下一物体并停止连续任务控制的传送带。
- D455 静态复用原停止流程；动态模式在当前物体释放及正常返回准备位后暂停，不等整批 sort_dynamic 结束才响应。
- 没有在途抓取则立即暂停。手动启动的独立程序仍保留。
- 窗口异常消失：后台检测 UI 连接断开，执行同样的本轮后暂停。
- 再次打开：接回已有状态，不自动恢复连续抓取或重新发送激活/回零。
- “停止”与“急停”分开：停止按本轮收尾；急停立即走现有中断路径，不等待动画或弹窗。
- 急停后显示“复位”操作，复用现有明确的恢复逻辑；不要把复位偷偷合并进开始抓取。

### 3.4 碰撞保护后的恢复流程

用户现场事实：碰撞后机械臂自保护失能，现有人工办法是重新激活 CAN、重新激活机械臂、重新打开 T1。工作台把这套既有流程做成连接页“碰撞后恢复”按钮，主页状态提示可直接跳转，不自动重新使能。

操作顺序：

1. 用户点击“碰撞后恢复”；页面提示先移开碰撞障碍，说明流程包含重新使能，不增加勾选或重复确认。
2. 后台暂停任务派发、停止任务传送带，取消遗留规划/执行并丢弃旧任务队列；这是故障恢复，不等故障物体“正常完成”。
3. 正常停止本工作空间的旧 T1 进程组，确认旧实例退出；T1 未运行则进入下一步，不触碰其他工作树进程。
4. 完整重新执行原 CAN 激活命令和 cansend；不能使用普通“补齐缺少组件”逻辑跳过。
5. 重新执行 activate_robot.py，保留其原有协议序列。
6. 按当前已选 TCP/模型配置重启 T1/MoveIt；不能恢复成旧 TCP。
7. 更新动作端客户端和控制状态，取消旧目标、清旧队列及软件遗留忙碌/错误标记；默认不重启相机、YOLO 或 T5，不额外命令回零/回待机/开夹爪。
8. 展示命令结果与新 T1 的实际反馈，保持抓取暂停和传送带停止；由用户再次点击开始。

逐步显示执行中/完成/失败、原命令、输出和重试；某一步实际失败只结束本次恢复操作，不锁其他页面。不要把一次进程返回 0 直接写成“碰撞已解除”，等待实际通信与使能反馈；缺少某项反馈就显示“连接流程已完成，使能待确认”等真实状态。

识别规则：

- 优先监听当前 T1 的 /rosout，logger 为 agx_arm_ctrl_single_node，消息为 Agx_arm is not connected, cannot control；也监听当前 T1 运行日志以覆盖外部启动。
- 收到一次当前运行期警告即可标记“连接异常，建议恢复”；重复消息只合并展示计数和最近时间，原始日志保留。
- 历史日志浏览、旧 PID/上一轮 T1 的日志不得触发新故障状态。重启后按新运行实例刷新状态。
- 不自动推断原因是碰撞，也不自动发 CAN、Enable 或启动动作；按钮始终可手动使用，不依赖必须先检测到警告。
- _check_can_control 另有未使能和示教模式警告，分别显示中文原因，不能把示教模式当碰撞并自动退出。
- 代码核查发现 AgxArmStatus 的 err_status 字段当前未实际填充，不能把默认 0 解释为“无碰撞”；确认使能应使用实际 SDK 反馈或已有明确使能状态，不用 T1 PID 代替。

### 4.2 已有流程与改动边界

- 原动态预测、拦截、随动、夹爪、重试参数和策略原样复用。
- 静态抓取的识别、几何中心和接近流程原样复用。
- 必要改动仅限数据源选择、可配置放置去程、释放后返回，以及本轮后暂停。
- 新的放置方案在每个物体开始处理时解析并固定，包括当轮使用的参考位置；下一个物体读取最新配置。
- 去程按录制顺序通过 0～5 个关节途经点，最终到释放点，确认原有动作结果后按既有开夹爪流程释放；不额外加入人为等待。
- 复用各模式已有运动发送方法，不以“性能优化”为由替换拦截算法或放宽碰撞检查。
- 正常完成后动态显式回当前已有 _dynamic_ready_joints；不是回零，也不是使用 Dabai 固定观察位。失败和急停仍用原错误路径，不追加返程。

## 5. 位置、放置与参数

### 5.1 示教流程

1. 打开“调试 → 示教与放置点”，新建方案并命名。
2. 页面说明用户通过机械臂按钮进入示教，不在保存时自动切模式或自动移动。
3. 摆到途经点，点“读取当前位置”，显示 J1～J6 和 TCP，再点“添加途经点”；最多五个，可调整顺序、替换、移除。
4. 摆到终点，点“保存释放点”。
5. 点“保存方案”；主页面下拉框立即出现。
6. 待机位、Dabai 观察位同样从当前真实反馈保存，分别命名。
7. 提供“预览路线”只规划和显示、“执行示教路线”明确运动按钮；保存本身不运动。

保存关节角以 rad 为准，显示使用度；TCP 位置显示 mm、文件保存 m，姿态标明 RPY/四元数语义。不能用关节控制目标冒充实际反馈。实体示教时现有驱动是否仍持续发实际关节反馈，需要在执行验证中确认。

JSON 使用临时文件＋os.replace 保存，保留最后一次有效版本用于恢复；读取失败显示错误并继续显示已有有效快照，不改原文件。不要为此新增哈希检查。

### 5.3 参数分组与生效

| 参数组 | 内容 | 生效要求 |
|---|---|---|
| 手动规划 | 速度比例、加速度比例、目标关节/位姿 | 作用于下次手动规划，不偷偷改抓取速度 |
| 静态抓取 | 当前代码使用的接近、抬起、夹爪、释放等可调值 | 抽取现有常量，不改默认值；下一物体生效 |
| 动态抓取 | config/dynamic_grasp.json 当前已有字段 | 维持字段名、单位、值；下个物体新建 runner 时读取 |
| 相机 | 每台独立自动/手动曝光及对应值 | 原控制接口实际反馈后标记生效 |
| YOLO | 每台置信度、重叠抑制阈值、检测周期 | 现有仅声明 ROS 参数不等于已支持热更新；补帧边界提交并验证 |
| 标定 | 每台内参、手眼、公共 TCP 文件 | 按第 6 节受影响组件应用 |
| 位置 | 待机、观察、放置方案与类别映射 | 下一物体读取；位置按钮使用最新保存值 |
| 高级 | 原坐标管理、队列；传送带方向标定入口及现有文件 | 复用已有功能，不重写协议或算法 |

每项显示当前生效值、编辑值、单位和生效方式。“保存”写配置，“应用”执行更新；需要重启的列出具体组件并提供“重启受影响组件”。不自动重启其他无关组件，不在显示值改变时冒充后端已成功。

- TCP 原始候选：同目录 candidate.json，质量状态为 failed；当前采用副本在 data/calibration/imported/dual_camera_20261018/tcp_candidate_15_samples.json，活动文件 config/calibration/tcp.json。

活动 TCP 拟合 RMS 4.657449358089706 mm，最大 9.016730303577544 mm。它与原始候选的质量标签差异是历史接受记录，不得覆盖或伪造。D455 manifest 的 selected_for_verification 与 scene_verified=false 也原样保留；用户说动态性能已满意，不等于旧标定的质量标记自动改写。

### 6.3 图形化操作

- 标定页二级选择内参、手眼、TCP、验证，再选择相机；TCP 为公共工具参数。
- 按钮：启动采集、采集一组、撤回上一组、计算并保存、结束采集、查看结果、在参数页选用。
- Enter/d/q/c 对应现有交互。手眼 q 会结束采集并计算，TCP q 可计算后继续补采；页面忠实反映两者区别。
- 显示实时原图或现有 /handeye/debug_image，采样列表、数量、质量指标、文件路径、工具输出。
- 求解结果自动进入文件列表，但仅在用户“应用”时成为活动选择。
- 采样/求解失败保留已有数据，显示原错误；缺少可解数据时不编造结果。
- 标定算法和已有逐帧数据质量判定复用，不新增采样门限或强制审批步骤。

### 6.4 应用和验证

- 手眼或内参切换：备份被替换活动文件及 manifest；保存来源和原始质量信息。不要重写原始候选。
- 检测和手眼必须使用用户选择的同一套本相机 K/D；将当前 D455 文件内参路径能力推广到 Dabai，不混用某台驱动内参与另一套文件。
- 内参/手眼需要重载时，只重启共用双路检测节点与受影响 TF；明确说明共用检测器重启会短暂影响两路检测，不偷偷停相机驱动。
- TCP 是 SDK 与 MoveIt 模型共享参数，当前需重新启动 T1，不能用在线 ros2 param set 冒充应用。页面提供明确的应用并重启操作，保持旧启动时已有运动行为的说明。
- 质量指标是展示和选择依据，不以 passed/approved 标签另设应用审批；必要的数值、格式和坐标解释检查保留。对于结果没有数值解的文件，说明无法应用原因。
- 新应用操作不伪造 scene_verified、quality_status=passed 或人工验证记录；适配旧加载器，使用户主动选择且数值完整的结果可按真实状态加载。
- 手眼验证复用项目 TF/标定板核查流程并打开真实 RViz。D455 固定相机相对 base_link，Dabai 按 manifest 的 link6/TCP 语义变换，不能当固定 base 外参。
- TCP 验证复用现场主目录版本的固定点姿态摆动、参数和报告；界面提供角度、步数、轴、速度、规划、执行、停止。运动前显示“请将机械臂放到可活动、无遮挡的位置”，作为提示。
- 适配旧验证工具中按 T5/T6 节点存在性拒绝的逻辑，以及重复文字确认；按钮本身表达用户执行意图。继续使用原数学、模型和轨迹检查。

## 7. 六页界面与设计约束

### 7.1 全局

- 设计基准 1920×1080，按逻辑像素自适应；支持 1600×900，较小窗口局部滚动，急停始终可见。
- 左导航约 184 px；顶栏约 72 px；内容边距 20～24 px，卡片间距 12～16 px，圆角 8～12 px。
- 背景 #F5F7FA，卡片 #FFFFFF，正文 #111827，次级文字 #64748B，主蓝 #1769FF，细边框 #E2E8F0；红色仅急停/错误，绿色仅健康状态。
- 默认使用已安装中文无衬线字体，优先 Noto Sans CJK SC；正文 13～15 px，标题 22～28 px，按钮高 36～42 px。
- Lucide/Heroicons 风格线性图标，不使用 Emoji 作为图标。
- 页面切换 160～220 ms，悬停/按下 80～140 ms，抽屉展开 180～240 ms，使用 Qt 自带动画。
- 三维渲染和图像更新独立于页面过渡。急停、停止、执行命令立即发送，动画只反馈结果；不使用连续炫光或大面积模糊。
- 全局位置区：待机位、观察位、急停；观察位在动态模式显示“动态准备位”，Dabai 显示“观察位”，D455 静态显示现有适用参考位，工具提示解释实际目标。
- 顶栏健康项至少机械臂、D455、Dabai、YOLO、MoveIt、动作节点、传送带；容纳不下时合并“更多状态”展开，不用隐藏错误。
- 未启动、等待数据、正常、异常、未知分别显示，不能把“没启动驱动”断言为“物理设备坏了”。
- 主导航、操作、参数、对话框、错误摘要中文；原始日志和 ROS 名称原样显示，不请求外部翻译服务。

### 7.2 抓取主页

左相机列约 27%，中间三维约 44%，右操作约 29%，允许拖动；两路画面保持 4:3，缩放不拉伸，坐标点击按原图比例换算。

右侧从上到下：三种模式、统一/类别放置、方案或类别映射入口、模式对应的单次/连续按钮、检测目标列表、传送带、本轮状态。D455 静态显示“抓取所选目标”“开始自动分拣”“停止”；Dabai 只显示单次按钮；动态显示“开始动态抓取”“本轮后停止”。

三维只显示实际反馈和场景，默认不显示拖动目标球。底部显示真实 J1～J6 和 TCP，可展开更多。检测框颜色沿用识别样式，不把工程 UI 做成大面积彩色仪表盘。

### 7.3 调试

二级页签：运动调试、抓取参数、相机与检测、标定文件、示教与放置点、高级。

- 运动：大三维视图＋关节滑块和精确数字框＋TCP 位置/姿态；“读取当前位置”“规划”“执行”“停止”“清除预览”。
- 拖动末端支持平移和旋转；改变目标只动目标影子。修改关节或末端后显示目标已变化，重新规划再执行最新轨迹，避免执行旧目标。
- 规划采用当前真实关节作起点；实际模型和目标影子分别显示。末端平移/旋转单位明确。
- 示教：方案列表、途经点顺序、终点、读取和保存操作；参考位置独立管理。
- 标定文件：相机/类型筛选、日期/样本数/来源/误差/当前选中/当前生效列、导入、查看、应用、重启受影响组件、恢复上一个活动版本。

### 7.4 连接

顶部“一键启动全部”“刷新状态”。卡片至少 CAN、机械臂激活、机械臂/MoveIt、D455、Dabai、双路 YOLO、动作节点、两路 TF、传送带通信。各自启动/停止/日志入口按实际能力提供；CAN 激活不是长期进程，不显示假 PID。

顶部同时提供“碰撞后恢复”，展开第 3.4 节恢复步骤及日志。普通一键启动复用已有进程，恢复按钮明确重做 CAN/激活并重启 T1；两种操作不可混成同一个“已运行所以跳过”实现。

一键检查实际已有状态，不重复激活已正常机械臂，不重复加载模型。CAN→激活→机械臂/动作属于原命令顺序；两个相机/TF/视觉可独立启动。某组件失败不回滚已经成功组件，不阻止无关操作。启动过程显示每项结果和取消尚未开始步骤的按钮。

保持原 CAN 命令可见：

~~~bash
bash ~/agx_arm_ws/src/agx_arm_ros/scripts/can_activate.sh can0 1000000 && cansend can0 123#1122334455667788 && ip -s link show can0
/usr/bin/python3 /home/lxf/agx_arm_ws/activate_robot.py
~~~

运行时路径解析为所选工作空间，命令显示实际绝对路径。既有脚本需要系统认证时走一次正常终端/系统认证交互，不保存密码，不配置免密 sudo，不把整个工作台作为 root 运行。

### 7.5 标定、采图、日志

标定按第 6 节；采图默认 2 秒间隔，可更改，单张立即取下一张新帧；双路分目录并记录各自时间戳，不假称同步。PNG 原始彩色图不加检测框；导出目录或 ZIP，附会话信息，不生成伪标注。

日志页提供来源、时间、级别、关键词筛选、暂停滚动、原文详情、复制、打开目录、导出。保留所有已有输出和 traceback，尽可能详细；避免为每帧增加大量重复日志而拖慢推理。界面最多保留最近 10000 行并按需加载历史；不自动删除用户日志。

日志页二级入口“动态抓取诊断”列出已有 data/diagnostics/dynamic_grasp/*.json，展示报告、阶段/轨迹数据；报告存在什么就展示什么，不补造图像或完整物理动画。

### 7.6 预览图的效力

计划中嵌入六页图片，并使用项目内相对路径保存，离开本会话仍可打开。图片决定布局、色彩和视觉层次；本规格决定按钮行为、真实数据源、文件格式和中文文案。生成图片中的示例误差、帧率、相机分辨率、模型外形和英文分类名不能覆盖实际规格。

已确认的主页原图保留为参考，包含“1280×960”“Dabai 30 FPS”等生成错误；实现使用本规格 640×480@30 / @15。三维加载实际项目模型，不使用生成图中的机械臂图片。

其他图片的模型权重名、波特率、角点数、标定误差、旧日期和简化路径也只是生成示例。详细修正表见实施计划第 5.8 节。六张实际生成图尺寸均为 1672×941；布局基准仍为 1920×1080 逻辑像素。

## 8. 完成定义

软件阶段的完成必须同时具备：

1. 可从桌面启动，代码与资源在项目内，关闭 Codex 不影响使用。
2. 六页布局和交互符合此规格，中文为主。
3. 双相机实际画面、检测结果和真实三维模型可联动，模式切换不重启视觉链路。
4. 三类抓取调用原后端，放置方案、返回位置与本轮后暂停行为正确。
5. 现场格式的采样、求解、应用和验证可由按钮操作，实际生效状态真实。
6. 独立/一键启动、部分失败继续、重连和日志可用。
7. 单张/定时采集导出的原图可直接交给 YOLO 标注流程。
8. 提供针对性离线检查证据和用户现场验证记录；未实测项目明确标记。
9. 没有覆盖主目录未提交修改、共享环境、权重、旧标定和实验数据。
10. 只清理本任务确认无用的临时文件；交付说明清理大小与回收站状态。
11. 未连接警告能提示人工恢复，恢复确实重做原连接流程，既不自动重新使能，也不自动续抓。
