## 原因与实际修改

1. **RViz 闪烁**：Humble RViz/Ogre 在高分屏下的原生窗口尺寸与 Qt 逻辑像素不一致。工作台进程使用原生像素渲染，再独立按桌面 DPI 补偿界面尺寸、文字和图标；不修改系统 Qt/ROS、桌面缩放。保持渲染窗口固定父对象，并让几何更新和目标编辑状态更新具有幂等性（重复刷新不会重复设置相同状态）。用户现场确认闪烁消失。[上游问题](https://github.com/ros2/rviz/issues/1052)、[尺寸修复讨论](https://github.com/ros2/rviz/pull/1870)。
2. **YOLO 缺失权重**：本树漏准备 `models/yolo/fruits12.pt`，补上到既有只读模型的忽略软链接。复用原 Python/CUDA 环境，未下载或替换模型；实际双路节点已启动并输出检测结果。
3. **sudo**：本树 `.runtime/workbench-credentials.json` 为 0600、被 Git 忽略，使用 `sudo -S -p ''` 的标准输入传入凭据；不把密码拼接进 argv。手动点击 CAN/机械臂激活会重新执行，避免 USB 重识别后被历史“命令已完成”缓存跳过。
4. **恢复被串口故障阻断**：先发送任务暂停/取消，再独立尝试停带；串口异常作为可见警告，继续恢复机械臂。
5. **旧 T1 遗留子进程**：原 launch 父进程退出后，旧驱动仍留在进程组。补充仅核验本树工作空间、UID、boot、session、启动时间及 `AGX_ARM_WS` 环境的子进程清理，分级 INT/TERM/KILL；不按名字批量杀进程。默认 CLI stop 行为保留，工作台显式使用这条清理路径。
6. **状态刷新**：过期关节反馈返回无新鲜反馈，不让整个 `status.get` 抛异常；恢复后清除旧实例的断连提示。恢复步骤失败时显示具体步骤和错误。
7. **关闭所有连接**：「连接与启动」新增红色按钮。先取消手动规划、暂停/取消抓取，停止图片采集和标定会话，再逐项关闭 T5、T1、双路检测、两个 TF、两台相机、传送带，最后关闭 CAN；工作台和后台保留。单项失败不阻断后续关闭，并在界面/日志列出未完成项。工作台启动的 T5 退出时不回待机、不松爪。该按钮通过假组件及隔离进程验证，没有为了测试而关闭用户全部实机组件。
8. **相机预览**：「相机与检测」两列分别增加 300×180 逻辑尺寸原图，页面可滚动。在图像断流时保留最后一帧，清楚覆盖“画面已暂停 · 上次更新 N 秒前”；原相机状态仍报告等待数据，不用旧图伪装在线。标定预览在调试图过期后回退至所选相机原图。
9. **日志突发**：逐次读取每个注册日志最多 64 KiB，保留偏移和不完整行，下次继续读，不丢弃磁盘原始日志。隐藏图像组件不做无用重绘。
10. **重复 RViz**：T1 原启动链会额外打开独立 RViz，本机该窗口会崩溃。父 launch 新增并转发 `use_rviz`，默认 true 保留原终端行为，工作台启动 T1 时显式 false，复用嵌入视图。当前恢复成功后没有为这项设置再次重启机械臂，后续启动生效。

### 2026-10-19 D455 高频掉帧复核

- 用户问原文：「d455掉线十分频繁，找一下原因，是不是两个相机共用一个yolo的原因」；随后补充：「yolo是用cpu计算的吗？得用我电脑的gpu啊」。
- 不是模型在 CPU 推理：Python 环境为 PyTorch 2.11 / CUDA 13，模型首次推理后在 `cuda:0`，日志明确输出 `YOLO GPU: NVIDIA GeForce RTX 4060 Laptop GPU`。
- `realsense2_camera` 启动日志报告 `Device USB type: 2.1`；USB 拓扑显示 D455、Dabai、CAN 和串口共用 `usb1/1-2` 的 480 Mbps 集线器链路，而电脑另有空闲的 USB 3 / 10 Gbps 根接口。
- 复现时 10 秒探针收到 D455 彩色 0 帧，但 D455 深度仍有约 22.8 帧/秒；由于没有彩色，aligned depth 与 YOLO 检测也为 0。驱动日志同时报 `Frames didn't arrived within 5 seconds`。
- 隔离共用 YOLO 进程后，15 秒内 D455 彩色恢复 184 帧；重新启动后再次出现断流。结论是 USB 2.1 带宽/链路是根因，YOLO 的 CPU 侧图像回调和标注编码会放大问题；拆成两个 YOLO 进程会增加同一台电脑的 CPU/显存负载，不能修复 USB 带宽。
- 工作台的状态现在读取 D455 的实际协商速率；USB2 会在相机统计行直接提示。相机帧率改为最近 2 秒窗口统计，画面断流后显示 0，避免旧的平均值继续误导。
- 硬件处置：把 D455 的数据线直接接到电脑 USB 3（蓝色/SS）口，不经过当前 USB 2 集线器；重新启动 D455 后，工作台应显示 `USB 3`，可用 `lsusb -t` 确认连线达到 5000/10000 Mbps。

### 2026-10-19 目标列表跳动与无法选中

- 用户现象原文：「我不能点击d455和dabai的点击当前选取目标来进行抓取，应该是目标一直在跳变，选中不了」。
- 连续采样确认 `/detection_info` 的 `motion_session` 未变化，检测会话本身没有每帧重建。
- 界面原因：同一检测同时经直接 ROS 桥和后台 IPC 两次进入窗口；目标表每次接收都先 `setRowCount(0)` 清空再重建，且选中绑定在鼠标释放后触发的 `cellClicked`，因此点击很容易被 10 Hz 刷新吞掉。
- 修复：只使用图像所在的同一路直接检测更新目标表；按稳定的 `track_id` 排序；原地更新行而不清空；鼠标按下时立即记录目标；表格只允许单选。未选目标执行单次抓取时会给出明确中文提示。
