## Git与运行文件的边界

源码、配置、活动标定参数、教程、已有测试代码和历史小型记录进入Git。新采集图像/点云、诊断输出、运行日志、虚拟环境、模型权重、构建/安装目录及本机锁不进入本次提交；本地文件保留。已有Git历史不重写，历史中曾提交的环境文件不会因为当前取消跟踪而从旧提交中消失。

当前工作树使用独立分支`codex/parallel-dev`。GitHub的main更新为本版；本地主目录main的原HEAD与暂存区保留，避免破坏尚未整理的迁移暂存记录。后续请在独立worktree从`origin/main`或本标签开始，不要直接在旧主目录执行pull/reset以处理这些记录。

```bash
git fetch origin
git worktree add -b codex/next-change /你自己的工作树目录 origin/main
```

这里的路径是示例，实际开发继续遵守`AGENTS.md`和`docs/parallel_development.md`。

## 新机器恢复

Git代码不等于完整运行环境：ROS2 Humble、CAN驱动、相机SDK、YOLO/GraspNet权重、共享视觉虚拟环境和Pinocchio仍需按README、config/deployment_manifest.json恢复。不得把现有install/build拷贝当作跨机器部署方式。主机相关资源路径在config/runtime.json及部署清单中说明。

标定包与TCP轨迹辅助包使用新树源码构建，不能假定旧install已经包含发布源码。当前现场进程与安装目录未因Git发布改变，运行流程不受此次整理影响。
