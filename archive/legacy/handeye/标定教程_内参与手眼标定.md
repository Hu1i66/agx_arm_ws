# 相机标定教程：内参标定 + 手眼标定（ChArUco 7×5 标定板）

> 本教程覆盖 4 件事：**① 内参标定、② 手眼标定**，分 **眼在手上（Orbbec Dabai DC1）** 与
> **眼在手外（Intel RealSense D455）** 两种场景。
> 所有命令都已按你工作空间的相机话题与命名空间写好，可直接复制执行。

---

## 0. 场景与相机分配（先对号入座）

| 场景 | `mode` | 相机 | 彩色图话题 | 内参话题 | 标定板位置 |
|---|---|---|---|---|---|
| **眼在手上** | `eye_in_hand` | Orbbec Dabai DC1 | `/dabai/color/image_raw` | `/dabai/color/camera_info` | 平放在**桌面**，标定全程不动 |
| **眼在手外** | `eye_to_hand` | Intel RealSense D455 | `/camera/camera/color/image_raw` | `/camera/camera/color/camera_info` | **刚性固定在机械臂末端**，相机不动 |

两种场景的标定结果含义不同（下游与验证流程必须按此处理）：

| 场景 | 标定结果 | TF 方向 | 验证时是否需要取共轭 |
|---|---|---|---|
| 眼在手上 | `T_cam2gripper`（相机在 TCP 系下） | `tcp_link → 相机` | **需要**（xyz 取反，w 不变） |
| 眼在手外 | `T_base2cam`（相机在 base_link 系下） | `base_link → 相机` | **不需要**，直接用 |

**两个相机必须各自标一份内参**，不要混用（分辨率/模组都不同）。

## 1. 标定板参数（唯一真相源）

| 参数 | 值 |
|------|-----|
| 方格阵列 | 7 × 5（列 × 行） |
| `square_length` | **0.032 m**（用卡尺实测后可用 `-p square_length:=<实测值>` 回填） |
| `marker_length` | **0.024 m** |
| 字典 | `cv2.aruco.DICT_5X5_1000` |
| 标记 / 内角点 | 17 个（id 0–16）/ 24 个（6×4） |
| 板面尺寸 | 224 × 160 mm；原点在左上角，x 向右、y 向下 |

### 打印与验收（三步，缺一不可）

1. 打印选“**实际大小 / 100%**”，**禁用**“适应页面 / 缩放 / 无边距扩展”。
2. 量尺验证：页脚 100 mm 标尺实测应为 **100.0 mm**（±0.5 mm）。
3. 平整度（隐藏项）：纸卷曲 1–3 mm 会直接污染外参 → **整面喷胶贴在铝板/亚克力板上**（不能只贴四角）。

### 3.4 锁定曝光/增益/白平衡（文档硬要求，别跳过）

```bash
# Dabai DC1 —— 先确认类型，再关自动曝光并固定曝光值
ros2 service type /dabai/set_color_auto_exposure      # 实测为 std_srvs/srv/SetBool

# D455 —— realsense-ros 动态参数

ros2 param set /camera/camera rgb_camera.exposure 100
```

固定曝光后画面可能偏暗/偏亮，**先把曝光值调到画面亮度合适再开始标定**，中途不要改。
（若上面两个服务的类型与实际不符，用 `ros2 service type` 的输出为准调整消息类型。）

## 4. 内参标定

### 4.1 为什么必须自标

- **不要用厂商出厂内参**：出厂值常与你的实际模组有偏差，且畸变系数可能缺失。
- **内参必须与采集时的分辨率一致**：用 1280×720 标的内参去跑 640×480 采集，角点/位姿会整体偏掉。
- **位姿必须覆盖画面四角与边缘**：只在画面中心采样，`k1/k2/k3` 无约束，畸变误差会被外参吸收。

### 4.2 通用操作

用**同一块 ChArUco 板**标定（无需额外棋盘格）：

| 按键 | 功能 |
|------|------|
| **Enter** | 采集一帧 |
| **d** | 回退上一帧 |
| **q** | 计算内参并写入 YAML（需 ≥15 帧） |
| **c** | 退出 |

要求：**15–20 帧，覆盖画面中心与四角**（程序实时打印 `画面覆盖: N/9 格` 并提示缺失区域）。
每帧把板拿到不同位置/角度，**静止后**再按 Enter。距离控制在方格像素边长 ≥60 px 为佳
（§5.3 会看到这个值）。

### 4.3 眼在手上：标 Dabai 内参

```bash
# 终端 1 已启动 Dabai（§3.1）；终端 2：
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
cd /home/lxf/handeye
ros2 run handeye_calibration_ros camera_intrinsic_calibration --ros-args \
  -p image_topic:=/dabai/color/image_raw \
  -p camera_info_topic:=/dabai/color/camera_info \
  -p out_yaml:=./result/camera_intrinsics_dabai.yaml
```

### 4.4 眼在手外：标 D455 内参

```bash
# 终端 1 已启动 D455（§3.2）；终端 2：
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
cd /home/lxf/handeye
ros2 run handeye_calibration_ros camera_intrinsic_calibration --ros-args \
```

### 4.5 验收与产物

```
result/
├── camera_intrinsics_dabai.yaml   # Dabai 内参 (眼在手上用)
└── camera_intrinsics_d455.yaml    # D455 内参 (眼在手外用)
```

YAML 含 `image_width/image_height`、`camera_matrix`、`distortion_coefficients`、
`reprojection_error`、`frames`、`coverage`。

| 判据 | 阈值 |
|------|------|
| 重投影误差 RMS | **< 0.3 px** 为佳；≥0.5 px 程序会告警，需重采 |
| 覆盖 | 中心 + 四角**全覆盖**（缺了会明确告警） |
| 分辨率 | 与后续手眼标定采集时**完全一致** |

> 若报告覆盖不足或 RMS 偏大，优先检查：运动模糊（静止后再采）、曝光是否漂移、板面是否平整。

## 5. 手眼标定

> 检测逻辑已**内联**在标定节点里（ChArUco 检测 + PnP + 质量门 + 落盘），
> **不再需要**启动 `aruco_ros single` 节点。

### 5.1 通用：启动机械臂（示教模式）

```bash
source ~/agx_arm_ws/install/setup.bash
ros2 launch agx_arm_ctrl start_single_agx_arm_moveit.launch.py \
  can_port:=can0 arm_type:=piper effector_type:=agx_gripper
```

> 机械臂切到**示教模式**，以便手动拖动。

### 5.2 通用：可选查看检测画面

```bash
ros2 run rqt_image_view rqt_image_view
```

选话题 **`/handeye/debug_image`**（不是原始图）。画面叠加显示：检出角点、板面坐标轴，
以及一行质量指标 `m17/17 c24/24 rms0.21px sq100px`；**不通过质量门时这行数字变红**。

### 5.3 场景一：眼在手上（Dabai）

#### 物理布置

1. 相机固定在机械臂手腕，**整个标定过程不动相对机械臂的安装**（紧固好，别松动）。
2. **标定板平放在桌面，用胶带粘死，全程绝不碰**。
3. 标定板距离相机 **15–25 cm**（以 §5.4 的 `sq` 值为准，≥60 px 最佳）。
4. 板面尽量正对相机，运动时始终完整在视野内。

#### 启动标定

```bash
# 终端 1: Dabai (§3.1)  终端 2: 机械臂 (§5.1)  终端 3:
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
cd /home/lxf/handeye
ros2 run handeye_calibration_ros handeye_calibration --ros-args \
  -p mode:=eye_in_hand \
  -p image_topic:=/dabai/color/image_raw \
  -p camera_info_topic:=/dabai/color/camera_info \
  -p intrinsics_yaml:=./result/camera_intrinsics_dabai.yaml
```

> **必须显式指定 `intrinsics_yaml`**：默认值是 `./result/camera_intrinsics.yaml`，
> 用分场景命名后它找不到文件，就会退化成用 `camera_info` 的出厂内参。

#### 采集

| 按键 | 功能 |
|------|------|
| **Enter** | 采集一组（走质量门；不合格**不计数**并当场提示原因） |
| **d** | 删除上一组（同时删除该帧原始图像） |
| **q** | 计算标定结果并保存 |
| **c** | 退出 |

拖动机械臂让相机换视角，按 **方位跨度优先** 配方采集 **15–25 组**：

1. 中心正视 1 个（基准帧，先确认检出正常）
2. **绕两个轴各 ±25–35° 倾斜**，每轴 6 个方向（上下左右 + 两个对角）——**跨度的主要来源**
3. **绕光轴自转** 4 个角度（0/90/180/270°）——只转图像不换视野，性价比最高
4. 距离 ±20% 变化 3 个（加强深度方向约束）
5. 至少 4 个位姿让板出现在画面**四角**（畸变约束全靠这些帧）

程序会持续打印 `[跨度提示] 当前相对转角中位 X°`；**低于 25° 会提示你补跨度**。

#### 验收

按 `q` 后看打印的判据表（按可信度排序）：

| 判据 | 阈值 |
|------|------|
| **留出位姿验证**（最硬，留 4 组不参与求解） | 平移误差 **< 1 mm** |
| 双算法一致性（病态报警器） | **< 0.02°**，超过 → 回去补方位跨度 |
| 相对转角中位 | **≥ 25°**（理想 30–40°） |
| 可用运动对数（≥25°） | **≥ 10** |
| 单帧重投影 RMS | < 0.5 px（数据质量，不是标定精度） |
| 方程残差 ‖A·X−X·B‖ | **仅参考，不作为验收** |

`cv2.calibrateHandEye` 的 5 种方法会作为交叉参考表打印（含与主解的旋转差）。

### 5.4 场景二：眼在手外（D455）

#### 物理布置

1. 相机用支架固定在外部，**整个标定过程绝不移动相机**。
2. **标定板刚性固定在机械臂末端**（夹爪/法兰），要求：
   - 绝不能有松动/位移/旋转——**1 mm 的晃动会导致结果漂几十厘米**
   - 板面朝相机，且安装位置不妨碍机械臂做绕三轴各 **25–35°** 的旋转
   - 胶带只粘四角白边或背面，不覆盖黑色边框与内部图案
   - 打印纸整面贴在硬板上，不能弯曲
3. 相机与板距离 **0.3–0.45 m**（以 `sq` ≥60 px 为准）。
4. 不需要知道板相对 TCP 的位置/角度——手眼标定会自动消去这个未知量。
5. 拖动时小心板撞到相机。

#### 启动标定

```bash
# 终端 1: D455 (§3.2)  终端 2: 机械臂 (§5.1)  终端 3:
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
cd /home/lxf/handeye
ros2 run handeye_calibration_ros handeye_calibration --ros-args \
  -p mode:=eye_to_hand \
  -p image_topic:=/camera/camera/color/image_raw \
  -p camera_info_topic:=/camera/camera/color/camera_info \
  -p intrinsics_yaml:=./result/camera_intrinsics_d455.yaml
```

> `mode:=eye_to_hand` 是**必须参数**（默认是 `eye_in_hand`）。
> 该模式下程序内部会对 TCP 位姿取逆后再求解，**输出的仍是 `T_base2cam`**。

#### 采集

按键与采集要求同 §5.3：**15–25 组，方位跨度 ≥25°**，中途**绝不碰相机和标定板**。
每组采集时程序会额外打印一行 `TCP(原始)` 便于核对。

#### 验收

判据表与 §5.3 完全相同。

## 6. 结果与 TF 验证

### 6.1 产物

```
result/
├── <时间戳>_calibration.json    # position / orientation / rpy + criteria(判据实际值)
├── <时间戳>_raw_data.json       # 原始位姿数据
└── <时间戳>_session/            # frames.json + f000.png ... 原始图像（支持离线复算）
```

结果 JSON 形如：

```json
{
    "position": [0.673, 0.011, 0.597],             // 相机在 base_link 系下的位置 (m)  ※眼在手外
    "orientation": [-0.693, -0.712, 0.088, 0.067],  // 四元数 (qx,qy,qz,qw)
    "rpy": [[-2.920, 0.027, 1.600]],                // 欧拉角 (rad)
    "criteria": { "holdout": {"median_mm": 0.42}, "...": "判据实际值" }
}
```

### 6.2 先确认相机坐标系名

`verify_handeye.launch.py` 的 `child_frame` 要用**相机树的根坐标系**，两种相机不同：

```bash
# Dabai
ros2 topic echo /dabai/color/camera_info --field header.frame_id
# 预期形如 dabai_color_optical_frame
ros2 run tf2_tools view_frames          # 生成 frames.pdf 确认实际名字

# D455
ros2 topic echo /camera/camera/color/camera_info --field header.frame_id
# 预期形如 camera_color_optical_frame（其祖先含 camera_link）
```

### 6.3 场景一：眼在手上（Dabai）—— 取共轭

编辑 `src/handeye_calibration_ros/launch/verify_handeye.launch.py`：

```python
# position 直接使用
x = "标定结果 position[0]"
y = "标定结果 position[1]"
z = "标定结果 position[2]"

# 眼在手上: 结果 T_cam2gripper 是"相机→TCP", TF 需要"TCP→相机", 所以取共轭 (xyz 取反, w 不变)
qx = "标定结果 orientation[0] 取反"
qy = "标定结果 orientation[1] 取反"
qz = "标定结果 orientation[2] 取反"
qw = "标定结果 orientation[3] 不变"

parent_frame = "tcp_link"
child_frame  = "dabai_color_optical_frame"   # 以 §6.2 实测为准
```

### 6.4 场景二：眼在手外（D455）—— 直接用

```python
# 眼在手外: 结果本身就是 T_base2cam, TF 也是 base→cam, 方向一致, 不取共轭
x, y, z = "标定结果 position[0]", "标定结果 position[1]", "标定结果 position[2]"
qx, qy, qz, qw = ("标定结果 orientation[0]", "标定结果 orientation[1]",
                  "标定结果 orientation[2]", "标定结果 orientation[3]")

parent_frame = "base_link"
child_frame  = "camera_link"
```

### 6.5 启动验证

```bash
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
ros2 launch handeye_calibration_ros verify_handeye.launch.py
```

在 RViz 中：

1. **Add → TF** → 展开 `parent_frame` → 看相机坐标系是否挂在**实际物理位置**附近
   （眼在手上应距 TCP 约安装距离；眼在手外应落在相机支架处）
2. **Add → PointCloud2** → `/camera/camera/depth/points`（D455）；Dabai 用 `/dabai/depth/points`（若未开点云则跳过）
3. 移动机械臂，观察点云/机械臂模型是否一致且**无漂移**——无漂移即验证通过
4. 若 TF 里找不到，用 `ros2 run tf2_tools view_frames` 确认实际 frame 名

## 7. 离线复算（不重做实验就能重解）

会话目录的 `frames.json` + 原始图像可事后换阈值/换算法/剔除坏帧重解：

```bash
source /opt/ros/humble/setup.bash
source /home/lxf/handeye/install/setup.bash
cd /home/lxf/handeye
python3 - <<'PY'
import json, sys, numpy as np
sys.path.insert(0, '/home/lxf/handeye/src/handeye_calibration_ros/handeye_calibration_ros')
import axxb
session = 'result/<时间戳>_session'          # 换成你的会话目录
frames  = json.load(open(f'{session}/frames.json'))
T_g2b = np.array([f['T_g2b'] for f in frames['frames']])
T_t2c = np.array([f['T_t2c'] for f in frames['frames']])
r = axxb.solve_axxb(T_g2b, T_t2c)
print(axxb.format_criteria_report(r, axxb.holdout_validate(T_g2b, T_t2c)))
PY
```

## 8. 故障对照表

| 症状 | 根因（按概率） | 处置 |
|---|---|---|
| `module 'cv2.aruco' has no attribute 'CharucoBoard'` | 用了系统 OpenCV 4.5.4 | 确认 `cv2.__version__` ≥4.7；**运行时不要设 `PYTHONNOUSERSITE=1`** |
| 编译报 `option --editable/--uninstall not recognized` | `~/.local` setuptools 83.x 与 Humble 构建不兼容 | 编译时加 `PYTHONNOUSERSITE=1` |
| `ros2 launch` 启动标定 exit code 255 | stdin 非 TTY 触发 termios 异常 | **必须用 `ros2 run`** 启动标定程序 |
| 平移误差 10–30 mm、旋转误差 1–2° | **方位跨度不足**（几乎没换视角） | 补 ±25–35° 倾斜 + 绕光轴自转（§5.3） |
| 结果每次都不一样 / 差几十厘米 | 板中途被移动、板松动、相机被碰 | 板固定死；眼在手外必须刚性固定在末端 |
| 采集一直提示质量门不通过 | 太远/太偏/模糊/曝光漂移 | 靠近、让板完整入画、锁定曝光（§3.4） |
| `sq` 方格像素边长 <40 px | 距离太远或彩色分辨率太低 | 靠近，或提高彩色流分辨率（**同时重标内参**，分辨率必须一致） |
| 内参提示“覆盖不足缺某格” | 只在画面中心采样 | 把板推到画面中心与四角重采 |
| 离线复算/在线结果对不上 | 内参 YAML 分辨率与采集分辨率不一致 | 统一分辨率后重标内参 |
| 想用出厂内参省事 | 出厂值与实际模组有偏差、缺畸变 | 按 §4 自标内参 |
| 平移误差随离轴距离线性增大 | 打印缩放（尺度错）或单位混用 | 量 100 mm 标尺；用 `-p square_length:=<实测>` 回填 |
| 边缘区域误差明显更大 | 畸变未充分约束（画面边缘无样本） | 补四角位姿重标内参、重采手眼位姿 |
| Dabai 起点云/IR 报错 | USB2.0 带宽不足 | 保持 `enable_point_cloud:=false`、`enable_ir:=false` |
| Dabai 对齐失败 | 硬件 D2C 不可用 | `align_mode:=SW` |
| 检测不到板 | 距离/角度/光照，或板不在彩色图里 | 看 `/handeye/debug_image` 确认是否画出绿角点 |
